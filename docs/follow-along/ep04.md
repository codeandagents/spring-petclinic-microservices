## Step 1. Meet the team

Open the four files and read them: `.claude/agents/architect.md`, `developer.md`, `reviewer.md`, and

`description`.

## Step 2. The bug

In the browser: `http://localhost:8080` -> Find owners -> George Franklin -> Edit Pet (Leo) -> set the birth date's
year to 2027 -> Submit. **Look for:** nothing happens. That's upstream issue #557. Check it yourself:

```bash
curl -s -i -X PUT localhost:8080/api/customer/owners/1/pets/1 -H "Content-Type: application/json" \
  -d '{"id":1,"name":"Leo","birthDate":"2027-09-07","typeId":1}'
```

**Look for:** `HTTP/1.1 400` and a body with `status` and `error`, but **no `errors` list**.

## Step 3. Hand it to the team

Run `claude` (stay in auto mode) and paste:

Expect 10-25 minutes. **Look for:** the architect's plan in `docs/plans/`, the developer's tests failing first,

```bash

```

**Look for:** all tests passing. That proves the Java side only (see step 5).

## Step 5. Try it in the browser

Reload with **Ctrl+F5**, edit Leo, set the year to 2027. **Look for:** the app's own message under the date,
"Birth date cannot be in the future.", before you submit. Click Submit anyway: the browser adds its own warning
on top (the date input now has a `max`; each browser words it differently). If the page is blank instead (it
was in the video), open the browser's console: a `SyntaxError` in `httpErrorHandlingInterceptor.js` means the
script doesn't parse. Check it yourself:

```bash
node --check spring-petclinic-api-gateway/src/main/resources/static/scripts/infrastructure/httpErrorHandlingInterceptor.js
curl -s -i -X PUT localhost:8080/api/customer/owners/1/pets/1 -H "Content-Type: application/json" \
  -d '{"id":1,"name":"Leo","birthDate":"2027-09-07","typeId":1}'
```

**Look for:** no output from `node --check`, and now a body with an `errors` list: field `birthDate`, message
"Birth date cannot be in the future".
